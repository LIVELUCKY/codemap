codemap
Why Commands Agents GitHub

Your agent asks once and gets the code.

codemap indexes the definitions, references and routes of your workspace, across repositories and languages. A coding agent finds what it needs in one call instead of a chain of greps and file reads.

curl -fsSL https://raw.githubusercontent.com/LIVELUCKY/codemap/main/install.sh | sh

Installs one binary and connects the agents on your machine. macOS and Linux.


      

    

  






  

    

      

        
Searching is where an agent spends its turns.

        
To find one thing in a large code base, an agent greps, reads a file, greps again and reads some more. Each step is a round trip to the model, and every result stays in its context, most of it lines nobody needed.

        
Grep also cannot tell a definition from a mention, does not follow a name from Kotlin into Swift, and has to be told which repository to look in.

        
codemap answers the question the agent actually has, as one short ranked list. Main code comes before tests and generated files, and a single definition comes with its code.

Measured on a real workspace.

        
Five repositories, about 5,300 files. Nine navigation questions, three runs each, with Claude Haiku in headless Claude Code and read-only tools. Nothing told the model which tool to prefer; it reached for codemap by itself.

        
What the numbers do not say: codemap was not more correct on these questions, because grep gets them right too, and the bill was the same within a fraction of a cent. The gain is fewer round trips and less context spent on search output.

One command for most questions.

      

        
codemap BookRoute
Where it is defined, with its code. Works with half a name or a typo.

        
codemap token refresh
A few words when you do not know the name. Searches by words and by meaning.

        
codemap ic_logo
A file or an asset by its name, with or without the extension.

        
codemap uses BookPort
Who calls or references it, in every language and repository.

        
codemap impl BookPort
What extends or implements it, tests last.

        
codemap link '/api/v1/books/{id}'
The client, the server and the tests of one endpoint.

        
codemap grep 'retry|backoff'
A regex over every repository at once, gitignored files left out.

        
docker logs api | codemap logs
The gist of a log: repeats counted, errors first, stack traces kept.

      

    

  


  

    

      

        
Works with the agent you already use.

        
Claude Code gets a plugin: a short session prompt, and a hook that answers the agent's own grep and rg calls from the index. Every other agent gets four MCP tools.

        
codemap setup finds the agents on your machine and adds one entry to each. It keeps a backup of every file it touches.

Small on the outside.

      

        

          
Nothing to build or refresh

          
The index follows the git tree. A branch switch, a pull or an edit is seen on the next query, and only changed files are parsed again. Five repositories index in about a second.

        

        

          
35 languages, and files that are not code

          
tree-sitter grammars for Kotlin, Swift, TypeScript, Python, Go, Rust, Java, SQL, Terraform and more. Images and other assets are found by name, and by the layouts that use them.

        

        

          
Finds things you describe

          
A code embedding model is compiled into the binary, so "database access object for orders" finds OrderDao. Typos are corrected against the names in your own code.

        

        

          
Stays on your machine

          
No server, no account, no network call while answering. One binary, and git is the only thing it needs.
